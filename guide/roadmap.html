    SHADOW / ROADMAP

    Roadmap

    Proposals / not enabled features
    ○P0Encrypted off-device backup + restore drill

    Persistence and generations do not recover a lost SSD or deleted documents.

    Next
    Inventory existing backups; choose destination, quota, recovery credentials and retention before configuring Restic.
    Acceptance
    Restore documents, a password database and independent age/LUKS recovery material without relying on this laptop.
    Owner
    Future backup module + storage/preservation.nix
    Risk
    Recurring storage cost, sensitive key material and accidental overwrite during restore.
    ○P1Repeatable battery baseline

    There is no universal best power daemon; the screen and workloads may dominate.

    Next
    Compare balanced/power-saver and advertised 60/120 Hz modes with fixed brightness and workload. Record watts and task energy.
    Acceptance
    Repeat measurements, retain responsiveness, verify GPU sleep and restore the original profile/mode.
    Owner
    services/power.nix + wm/niri/config.kdl
    Risk
    One instantaneous sample is not a battery benchmark; do not stack tuning daemons.
    ○P1GPU sleep and suspend/resume acceptance

    RTD3 was observed working, but external displays, games and resume can change it.

    Next
    Check both GPU PCI functions after offload/monitor disconnect. Test lock, resume, Wi-Fi/audio and overnight unplugged drain.
    Acceptance
    No lost session, correct lock, repeatable drain and return to runtime suspension after workloads finish.
    Owner
    hardware/graphics.nix + pinned Razer module
    Risk
    Save work; unsupported deep sleep or hibernation must not be forced.
    ○P1Scrub/SMART alerts and ephemeral state

    Scrub and SMART already exist; scheduling is not proof of completed work or delivered warnings.

    Next
    Inspect unit state paths, completed scrub history, missed timers and smartd notification delivery. Persist only justified paths.
    Acceptance
    An alert reaches you, a scrub completes, and relevant history survives reboot; document new persistence entries.
    Owner
    storage/default.nix + storage/preservation.nix
    Risk
    Background I/O costs battery; single-device scrub cannot repair every corruption.
    ○P1Reviewed updates and known-good retention

    Latest kernel + beta driver + unstable creates a large regression surface.

    Next
    Adopt weekly review/security updates, targeted input bumps and post-reboot checks. Inspect cleanup retention before deleting generations.
    Acceptance
    Build/test/boot checklist passes and a known-good boot generation remains reachable.
    Owner
    flake.lock + core/nix.nix + core/boot.nix
    Risk
    Neither stale pins nor frequent unreviewed updates are safe; Flatpaks update independently.
    ○P2Review actual session and network protections

    AppArmor enablement is not profile coverage; a VPN icon is not a routing test.

    Next
    Reproduce PAM workaround, inspect actual confinement, VPN IPv4/IPv6/DNS and captive portals, review app permissions and device groups.
    Acceptance
    Document effective protections and necessary exceptions with a reproducible removal test.
    Owner
    desktop/greetd.nix + networking/ + security/
    Risk
    Authentication, DNS and USB policy changes can lock you out or break connectivity.
    ○P2Evaluate Lanzaboote Secure Boot

    Disk encryption does not establish boot-artifact integrity.

    Next
    Verify firmware recovery, vendor keys, ESP capacity and external credentials; build signed artifacts before considering enrollment.
    Acceptance
    Verified recovery, signed boot, functional NVIDIA/OpenRazer, boot rollback and protected independent PKI backup.
    Owner
    Future host-selected boot module + persistent signing keys
    Risk
    Firmware mistakes can prevent boot. TPM unlock is a separate threat-model decision.
    ○P3Consider TuneD or TLP only for a measured gap

    Modern alternatives offer extra policy controls, not a guaranteed battery improvement.

    Next
    Check locked Nixpkgs integration and shell compatibility, then trial ONE backend with rollback to PPD.
    Acceptance
    Repeatable energy benefit without resume, USB, audio, Wi-Fi or responsiveness regressions.
    Owner
    services/power.nix
    Risk
    Backend/API compatibility and conflicting device policies; don't change for novelty alone.
